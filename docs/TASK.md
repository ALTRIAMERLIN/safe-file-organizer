# 本轮施工指令（虹夏下达，规格以 docs/SPEC.md 为准）

1. 先完整读 docs/SPEC.md（Codex 规格 v1.0）。把要求映射为 docs/REQUIREMENTS.md、docs/DESIGN.md、docs/TASKS.md，然后才写代码。
2. 按规格第八节阶段顺序推进：阶段1 冻结规则与数据结构＋独立 fixture 预期 → 阶段2 核心扫描/规划/冲突与测试 → 阶段3 执行/日志/锁/恢复/撤销与故障注入 → 阶段4 CLI 与桌面界面 → 阶段5 Windows 干净安装与全套验收。阶段6（演示与素材）等功能验收通过后再说，本轮不做。
3. 每个阶段完成就：更新 PROGRESS.md（写明完成内容、测试命令与结果、未验证项）、本地 git commit 一次。能走多远走多远，不要为了赶进度跳过测试。
4. 验收证据：docs/ACCEPTANCE.md 逐项对应 A01–A27，记录测试名、实际命令、实际结果、证据位置；没跑的写未验证，不许勾选式造假。
5. 硬约束：不发布 GitHub、不推任何远程仓库、不碰 Upwork（规格第一节明示，本阶段只在本地）；所有文件操作测试只在临时沙盒内；禁止覆盖用户文件；实现不了的要求在 PROGRESS.md 写明原因，禁止删减安全要求或伪造通过记录。
6. 环境：本机 Windows、Python 3.11+；依赖必须可复现并写进 README 草案。
